# The Sourcegraph module owns every GraphQL document, typed by hand

One module, `sourcegraph`, owns every request sego sends and every response it reads. Its
`Client` has one method per question (`file`, `comparison`, `history`, `refs`, `search`), each
taking the client by value, since an invocation asks one question. Behind that interface the module
owns:

- the documents;
- resolution: the repository, the revision and the commit, each looked up once, the other host of
  `owner/name`, split guesses and the mirror's freshness;
- each question's request budget (ADR 0002), the raw read and the cache;
- the sorting of server errors, once, by where an error sits and what kind it is
  (`GqlError::kind()`, after `std::io::Error::kind()`).

It gives commands typed outcomes and `Error`s: no document, alias, JSON path or GraphQL error
crosses its interface. A fact that degrades (ADR 0014) is a `Result` field of the outcome. Commands
own sego's rules on top: windows, notes, headers and wording. Below it, the
`Transport` seam stays at HTTP, so cases pin the bytes of each request and record and live work.

The response types are written by hand with serde, not generated by `graphql_client` or `cynic`.
sego keeps no schema in the repository; the live drift check is the schema check (ADR 0011). Codegen
also handles poorly the selections that repeat at run time.

Each document is fixed text, with `@include(if:)` for the gitlab.com candidate of `owner/name` and
for optional parts, and `$first: Int` where text and JSON differ. Parts that can fail on their own
sit in nullable wrappers under the one revision lookup (ADR 0002). Two parts repeat a selection
instead: one per split guess of a web URL with a slashed branch, and one per path given to `diff`.
Both grow with the input, and the server has no field that resolves either. That was checked live
on 2026-10-25, along with the following:

- A skipped `String!` variable must still be sent.
- `null` sent for a `String!` that is in use fails with a pathless error.
- `first: null` means no limit.
- `fileDiffs(first: N)` returns a null `totalCount`, so the count keeps its own `first: 0` alias.
- `repositories(names:)` sorts its results, drops missing names and nulls all of `data` on failure,
  so `owner/name` keeps two `repository` aliases.
